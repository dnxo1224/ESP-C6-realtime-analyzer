# 부록: 실행 중 문제와 해결

### 문제와 해결 — empty 세션(830MB CSV) 파싱 병목
- 행동 세션(26MB)은 세션당 ~6초였으나 empty 3개는 pandas read_csv 안에서 **15분+ 정체**
  (워커당 CPU 660s+, dtype="string" × 3KB 인용 필드 64k행 조합의 병목으로 추정).
- 해당 워커 중단 → csv 모듈 기반 `parse_empty_fast.py`로 교체: **64,030행 읽기 4초**. 교훈:
  이 데이터 규모에서 pandas 문자열 파싱은 금물, 이후 파서는 전부 csv 모듈/스트리밍 방식.
