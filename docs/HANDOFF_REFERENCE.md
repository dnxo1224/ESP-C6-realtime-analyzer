## 0. 목표 시스템 (사용자 설명 기준)

```
ESP32-C6 ×5 (TX 1 + RX 4, 데이터셋 수집과 동일 펌웨어 계열)
  → TX가 RX 백홀 리포트 수집
  → GPIO로 ESP32-S3에 전달
  → S3가 2.4GHz WiFi로 서버에 전송 (RX별 원시 리포트 그대로)
  → Windows 노트북의 Docker 서버, DB에 적재
      평시: 대기 DB에 실시간 적재
      "추론 시작" 버튼 → 추론용 DB에 적재 + Python 가공 → 실시간 추론
```

서버 Python 코드가 구현해야 할 것: **동기화 → 보간 → 윈도우 조립 → 정규화·특징 → RF 추론 → 경보 로직**.
이 문서와 동봉 코드가 그 전 과정의 스펙과 구현을 제공한다.

## 1. 검증된 결론 요약 (왜 이 파이프라인인가)

3집(원룸 ~19m²) × 4인 데이터로 개발, **집×인물 이중 미지 12조합**으로 검증:

| 지표 | 값 |
|---|---|
| 윈도우 ROC-AUC | 0.930 |
| 낙상 이벤트 커버리지 (자동 임계값) | 98.6% |
| 오경보 | 순수 활동 스트림 외삽 9.7/h (walk가 주범, empty는 0.67/h) |
| 새 집 적응 | **부재 데이터만** — 정규화 통계는 1분에 수렴, 임계값 포함 10분 권장 |
| 추론 비용 | 윈도우당 ~78ms (CPU, RF 600트리) — 1초 주기 추론에 여유 10배 |

근거·전체 서사는 `docs/FINAL_REPORT.md`(필독), 실험 일지는 `docs/RUNLOG.md`.
설계상 절대 규칙: **새 집의 행동 데이터는 학습/튜닝에 쓸 수 없다. 부재 데이터만 쓴다.**

## 2. 데이터 계약 — 모델이 기대하는 입력

### 2.1 PHY (데이터셋 수집 = 새 C6 펌웨어, 동일 계열 확인됨)
- ch11 / HE20 (802.11ax SU) / MCS0 / CSI 512 bytes = 256 서브캐리어 × (I, Q)
- 프로브 **33 Hz** (TX broadcast, seq 번호가 시간 격자)
- 노드당 실효 수신률 25~33.5 Hz 관측 (결측은 보간으로 해결)

### 2.2 RX별 원시 리포트 (서버가 받게 될 것 — 데이터셋 rx{N}.csv와 동일 정보라고 가정)
필수 필드: `id`(=seq, **정렬·동기화 키**), `rssi`(dBm), `data`(512개 정수 = [i0,q0,i1,q1,...]).
그 외(노이즈플로어, 로컬타임스탬프 등)는 추론에 불필요. **local_timestamp는 노드 간 비교 불가**(클럭 독립).

### 2.3 CSI 숫자 계약 (중요)
- `data`의 I/Q는 **int8 범위를 넘는다**: 관측 −130 ~ +178 → **int16으로 다뤄야 함**
- 이는 어딘가(펌웨어 또는 수집 파이프라인)에서 AGC/gain 보상이 곱해진 결과로 추정됨.
  **⚠ 이 변환의 정확한 위치·수식은 이 세션도 모른다** — §8 확보 목록 참조
- 서브캐리어 256개 중 **유효 246개**: null 10개 = {0,1,2,3,4,128,252,253,254,255} (가드+DC) 제외
- 진폭 = `hypot(I, Q)`. 위상은 사용하지 않음
- 집·노드별 진폭 스케일이 최대 31배 다름 (AGC 상태 차이) — 그래서 정규화가 파이프라인의 심장

### 2.4 노드 순서 규약 (물리 배치와 텐서 채널의 결속)
- 설치: 방을 위에서 볼 때 **TX 6시, RX1→RX2→RX3→RX4 반시계** (TX 양옆 = RX1·RX4)
- 텐서 채널 0,1,2,3 = rx1,rx2,rx3,rx4 **고정**. 서버는 MAC↔rx번호 매핑을 반드시 이 규약대로 유지할 것
- 이 기하 재현성이 집 간 일반화의 핵심임이 실험으로 확인됨 (임의 배치 금지)

## 3. 서버 전처리 스펙 (동기화 → 보간 → 윈도우)

1. **동기화**: seq를 키로 4노드 리포트를 33Hz 격자 슬롯에 정렬. 슬롯당 노드별 존재/결측 마스크
2. **보간**: 결측 슬롯은 그 노드의 이웃 수신 프레임으로 **진폭 도메인 선형 보간**
   (I/Q가 아니라 진폭에서). 실시간 구현: 프레임 도착 시 직전 결측 구간을 소급해 채움 —
   동봉 `src/realtime_inference.py`의 `RollingInterp` 클래스가 정본
   (데이터셋 근거: 결측의 98.6%가 ≤3프레임(90ms), 선형 보간으로 무손실 수준 복원)
3. **윈도우**: 길이 **W=200 슬롯(약 6.06초)**, 스트라이드 **33슬롯(1초)** → 1초마다 판정 1회

## 4. 정규화·특징 (정본: `src/dataset.py`, `src/features.py`)

입력 윈도우 `(200, 4, 246)` 진폭 → 두 체인의 특징을 concat → **2,168차원**:

- **N5 (노드 간 로그비율, 1,300차원)**: `l = log1p(amp)`; 채널 = 노드쌍 6개
  (0,1),(0,2),(0,3),(1,2),(1,3),(2,3) 순서로 `l[:,i]−l[:,j]` → (200,6,246)
- **N4z (부재σ 정규화 로그차분, 868차원)**: `d = diff(l, axis=t, prepend=첫행)` / `dsd`
  (`dsd` = 그 집 부재 캘리브 구간 로그차분의 노드×서브캐리어별 std) → (200,4,246)
- 각 체인: 서브캐리어 246 → 24대역 평균 축약 후, 대역×채널마다
  시간통계 4종(std, mean|Δ|, max−min, mean|x−x̄|) + FFT 파워 5대역(0–0.5/0.5–2/2–5/5–10/10–16.6Hz 로그합)
  = 9특징, + 전역 모션 프로파일 4종(mean/max/p90/std) — **순서 포함 정확히 `featurize()`대로**

## 5. 새 집 캘리브레이션 절차 (배포 시 1회)

1. 설치 직후 **부재(집에 아무도 없음) 10분** 수집 (최소 1~2분이면 정규화는 수렴하지만
   임계값 분위수 추정을 위해 10분 권장)
2. `dsd` 계산 (N4z용 — 유일하게 필요한 정규화 통계)
3. 부재 데이터 자체를 모델에 통과시켜 윈도우 점수 분포 획득 (~594윈도우/10분)
4. **자동 임계값**: `thr = min(1, Q₀.₉₉₉ + (Q₀.₉₉₉ − median))` — 부재 점수 분위수 앵커.
   ⚠ 고정 임계값(0.5)이나 학습셋에서 이식한 임계값은 **커버리지가 34%로 추락**함이 검증됨.
   반드시 이 규칙을 쓸 것. 정본: `src/eval_events.py::empty_quantile_threshold`
5. 전 과정이 `src/realtime_inference.py --calibrate`에 구현되어 있음 (synced.csv 입력 기준)

## 6. 추론 루프와 경보 로직

- 1초마다: 최신 200슬롯 윈도우 → 특징 → `model.predict_proba` → p
- **경보 병합**: p ≥ thr 연속 구간을 3초 gap으로 병합해 에피소드화
- **선택 필터 (권장)**: "낙상 후 정지 확인" — 경보 시작 후 8초 내에
  [모션에너지 < 2.0 × (부재 캘리브 에너지 q95)]가 1.2초 지속하지 않으면 기각.
  효과: 커버리지 손실 0으로 walk 오경보 −33%. 정본: `src/stillness_filter_analysis.py`
- 알려진 특성: 낙상은 **지속 고확률**(p 0.4~0.8), walk는 임계값 언저리 짧은 스파이크,
  handsup(제자리 상체운동)은 일부 환경에서 지속 오경보 가능 — 미해결 약점, FINAL_REPORT §8 참조

## 8. ⚠ 이 세션이 모르는 것 — 새 세션이 직접 확보해야 할 정보

1. **S3→서버 바이너리 와이어 포맷** (프레이밍, 엔디안, 필드 배치): 이 세션은 파싱 완료된 CSV만
   받았다. 펌웨어/게이트웨이 코드에서 확인 필요
2. **AGC/gain 보상의 위치와 수식**: CSV의 I/Q가 원시 int8이 아니라 보상 곱셈 후 값(±127 초과)임은
   확인했으나, 그 곱셈이 펌웨어에서 되는지 수집 파이프라인에서 되는지 모른다.
   **서버 파싱 결과가 데이터셋과 같은 스케일인지 반드시 검증할 것** (§9 체크리스트)
3. MAC 주소 ↔ rx1~4 번호 매핑 테이블 (설치 규약과 일치시켜야 함)
4. DB 스키마·추론 시작 트리거의 구체 구현 (기존 C5 테스트 코드 참조)

## 9. 파이프라인 검증 체크리스트 (서버 구축 후 순서대로)

- [ ] C6 스트림 파싱 → 노드당 수신률 25~33.5Hz 범위인가
- [ ] `len(data)==512` 위반 0건인가, I/Q 값 범위가 int16 내인가 (±127 초과값 존재가 정상)
- [ ] **스케일 검증**: 빈 방 10분의 노드별 중앙 진폭이 상식 범위(수~수백)이고 시간에 안정적인가
  (데이터셋 기준치: `docs/place_node_summary.csv` — 집마다 4~127로 달랐음, 절대값 일치는 불필요,
  안정성이 중요)
- [ ] 캘리브레이션 실행 → 부재 윈도우 점수 median이 낮고(예: <0.1) 자동 임계값이 그 위에 형성되는가
  (데모 기준치: med 0.027, thr 0.082)
- [ ] 리허설: 사람이 들어가 걷기 → 낮은 스파이크, 침대 안전낙상 → 지속 고확률 + 경보 (데모 타임라인
  `docs/fig14_demo_timeline.png`와 형상 비교)
