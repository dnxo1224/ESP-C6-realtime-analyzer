## 1. 요약 (TL;DR)

**목표**: 3개 원룸에서 수집한 ESP32-C6 CSI 데이터로 학습한 낙상 감지기를, **한 번도 본 적 없는
4번째 집 + 4번째 사람**에게 — 그 집의 **부재(빈 방) 데이터 10~30분만으로 캘리브레이션**하여 —
그대로 배포하는 방법을 찾는 것.

**결론 — 최종 레시피** (집×인물 이중 미지 12조합 검증):

| 구성 요소 | 채택안 |
|---|---|
| 전처리 | seq 격자(33 Hz) 정렬 → 진폭 → 결측 선형 보간 |
| 정규화 | **노드 간 로그비율(N5) + 부재σ 정규화 로그차분(N4z) 특징 결합** |
| 윈도우 | 200패킷(약 6초), 스트라이드 33패킷(1초) |
| 특징 | 서브캐리어 24대역 축약 후 시간통계 4종 + 스펙트럼 대역파워 5종 + 모션 프로파일 |
| 모델 | **Random Forest 600트리** (딥러닝은 이 데이터 규모에서 도메인 과적합으로 열세) |
| 임계값 | **새 집 부재 데이터 점수 분포의 분위수 자동 설정 (empty_q)** — 라벨 불필요 |
| 새 집 적응 | 부재 데이터만: 정규화 통계는 **1분이면 수렴**, 임계값 추정 포함 10분 권장 |

**최종 성능** (미지의 집 × 미지의 사람 12조합 평균, `results/06_final_A_union_all/`):

| 지표 | 값 |
|---|---|
| 윈도우 ROC-AUC | **0.930** |
| 낙상 이벤트 커버리지 (empty_q 임계값) | **98.6 %** |
| F1 (empty_q, 12조합 평균 / 최악 조합) | 0.698 / 0.636 |
| 오경보 | 9.7건/h (연속 활동 스트림 기준의 보수적 외삽 — 6절 참조) |

사용자의 원안이었던 **"부재 데이터 기반 정규화"는 유효**했고, 본 실험에서 두 가지가 더해졌다:
(1) 부재 *평균/표준편차*로 레벨을 맞추는 것(N2/N3)보다 **부재와 무관하게 정의되는 상대 표현
(노드 간 비율·시간 차분)이 더 강인**하며, 부재 통계는 차분의 스케일(σ) 보정에 쓸 때 가장 효과적.
(2) 부재 데이터의 진짜 킬러 용도는 **임계값 자동 설정** — 미지의 집에서 점수 분포 자체가 이동하므로,
그 집의 부재 점수 분포에 임계값을 앵커하는 empty_q 규칙이 고정 임계값(이벤트 커버리지 63%)을
98.6%로 끌어올린 결정적 요소였다.

## 2. 문제 정의

### 배포 시나리오
1. 새 집에 TX 1 + RX 4를 **규약 배치**(위에서 볼 때 TX 6시, RX1→4 반시계, TX 양옆이 RX1·RX4)로 설치
2. 설치 직후 부재 데이터 10~30분 수집 — 이것이 유일한 적응 데이터 (행동 데이터 수집·fine-tuning 불가)
3. 이후 33 Hz 실시간 스트림을 즉시 이진 분류: **낙상**(liedown, sitdown) vs **비낙상**(handsup, walk, 부재)

### 왜 어려운가 — 데이터가 말해준 것
- 집×노드별 중앙 진폭이 **4.1 ~ 127 (31배)** 차이 (AGC 상태·수집 세대 차이).
  정규화 없이 학습하면 모델은 행동이 아니라 "어느 집인지"를 학습한다 → 실측: 무정규화 AUC 0.22~0.49.
- v1 세대(home_A)는 **IQ의 20%가 ±127에서 클리핑** + 노드별 결측 최대 20%,
  v2 세대(home_C rx4)는 실효 분해능 3~4비트 — 서로 반대 방향의 품질 문제.
- 같은 4명이 3집 모두에 등장하므로, 집만 홀드아웃하면 인물 일반화가 검증되지 않음
  → **집×인물 이중 미지(dual-unseen) 프로토콜**을 표준으로 채택.

## 3. 데이터 (csi-home-dataset-v1.0)

3집(각 ~19 m² 원룸) × 4인 × 4행동 × 120초 + 집당 부재 1920초 = 51세션, 결측 0, sha256 전수 검증 통과.
ch11/HE20/MCS0, 256 서브캐리어 중 유효 246, 프로브 33 Hz. 상세는 데이터셋 README 참조.

- 낙상 프록시: 침대 위/걸터앉은 자세에서 옆으로 확 넘어지는 행동의 주기적 반복.
  모션 에너지 분석 결과 **버스트 간격 median 4.2초, P90 6.9초** (세션당 24~32 버스트)
  → 6초(200패킷) 윈도우면 낙상 세션의 어느 윈도우든 낙상 동작 또는 직후 상태를 포함
  → "낙상 세션의 모든 윈도우 = 양성"이라는 약한 라벨이 정당화됨 (`results/01_eda/03_*.png`).
- 부재 32분 내 통계 드리프트는 완만 (2분 청크 z-거리 평균 ≤ 0.65) → 부재 캘리브 유효
  (`results/01_eda/04_*.png`).
- home_A 결측은 98.6%가 3프레임(90 ms) 이하 → 선형 보간으로 복원 (`05_missing_structure.png`).

## 4. 방법

### 4.1 파이프라인
```
synced.csv (seq 격자) → 진폭 |H| (246sc × 4rx) → 결측 선형 보간
  → 정규화 변환 (아래) → 200패킷 윈도우 (1초 스트라이드)
  → 서브캐리어 24대역 축약 → 특징 (시간통계 4 + 스펙트럼 대역파워 5)/(노드×대역) + 모션 프로파일 4
  → Random Forest → 확률 p → empty_q 임계값 → 3초 병합 경보 에피소드
```

### 4.2 정규화 후보와 표기
| ID | 정의 | 캘리브 필요 |
|---|---|---|
| N0 | 원시 진폭 | – |
| N1 | 세션별 z-score (오라클) | 불가(비실시간) |
| N2 | (amp − μ_empty)/σ_empty | 부재 |
| N3/N3z | log진폭 − 부재 log평균 (z는 σ로 나눔) | 부재 |
| N4/N4z | log진폭 시간차분 (z는 부재 차분σ로 나눔) | N4z만 부재 |
| N5 | 노드 간 log진폭 비율 (4노드→6쌍) | 불필요 |
| N6 | 윈도우 내 표준화 | 불필요 |

### 4.3 평가 프로토콜 (누수 방지 규칙)
- 기본: leave-one-home-out(LOHO) 3폴드 스크리닝 → 최종: **집×인물 이중 미지 12조합**
  (학습 = 2집 × 3인 + 그 2집 empty, 테스트 = 남은 집의 남은 1인 + 그 집 empty 평가분).
- 각 집의 empty 앞 10분은 캘리브 전용(정규화 통계·임계값), 뒤 22분만 평가용 음성 스트림.
- 테스트 집 행동 데이터는 어떤 형태로도 학습·튜닝에 미사용. 조기종료/검증은 학습 집 인물 홀드아웃.

## 5. 실험 결과 요약

### P2 — 정규화가 전부다 (`results/02_norm_ablation/`)
LOHO, W=200, RF/LogReg/XGB 스크리닝:

| 체인 | 최고 AUC (모델) | 최악 폴드 |
|---|---|---|
| **N5 노드비율** | **0.832 (RF)** | 0.692 |
| N4 로그차분 | 0.772 (RF) | 0.660 |
| N4z | 0.763 (RF) | 0.639 |
| N3z 부재 기준 로그 | 0.740 (RF) | 0.631 |
| N2 부재 z-score (사용자 원안) | 0.705 (RF) | 0.519 |
| N1 세션 z (오라클) | 0.615 | 0.491 |
| N0 없음 | 0.49 | **0.04** |

- 무정규화는 붕괴. **의외로 "오라클" 세션 z-score도 나쁨** — 세션 통계에 행동 분산이 포함되어
  클래스 신호를 지움. 부재만으로 통계를 만드는 것이 우월한 이유.
- 절대 레벨을 맞추는 접근(N2/N3) < 레벨과 무관한 상대 표현(N5/N4) — AGC·클리핑·분해능 차이가
  심한 이 데이터에서 레벨 정보는 신뢰 불가.

### P3 — 딥러닝의 함정 (`results/03_model_ablation/`)
- CNN/ConvGRU를 정규화 텐서에 직접 학습: 다수 구성에서 **미지 집 AUC 0.1~0.4 (반전 붕괴)**.
  검증(미지 인물) AUC는 0.99 — **인물 홀드아웃으로는 도메인 과적합을 감지할 수 없다.**
  학습 도메인이 2집뿐이면 딥모델은 집 고유의 정적 패턴을 지름길로 학습한다.
- 차분 입력 + 윈도우 표준화 + TX 양옆 노드로 제한하면 회복: N4z+N6/CNN/rx1·4 = 평균 0.845(min 0.81).
- 그러나 RF(동역학 수작업 특징)가 안정성·재현성·연산량 모두 우위 → **최종 모델 RF**.
  (`deep_vs_rf_summary.png` 참조)

### P4 — 세부 선택 (`results/04_detail_ablation/`)
- **노드**: rx1·rx4(TX 양옆) 2개만 = 0.836/min 0.789 > 전체 4노드 N4z 0.763.
  반대편 노드(rx2·3)는 0.65 — **배치 규약이 보장하는 기하 재현성이 일반화의 핵심**.
  (P2 rx4가 3~4비트 분해능인데도 rx1+rx4가 최강 — 기하 일관성 > 신호 품질)
- **윈도우**: N5는 W300(0.850), N4z는 W200이 최적. 표준은 W200(지연 6초 + 1초 판정 주기).
- **라벨 정제**(버스트 포함 윈도우만 양성): N4에 +0.05, 최종 구성에는 이득 없어 미채택.

### P5 — 배포 요소 (`results/05_deployment/`)
- **캘리브 길이 공정 비교**(평가 구간 고정): K=1/2/5/10분 모두 AUC 0.82 내외 — **차이 없음**.
  N4z가 쓰는 통계(로그차분 σ)는 1분에 수렴. 임계값 분위수 추정까지 고려해 기본 10분 권장.
- 방법론 교훈: K를 바꾸면 empty 평가 구간 길이도 변해 AUC가 부풀 수 있음(혼입변수) —
  고정 평가 구간으로 재실험하여 확정.

### P6 — 최종 검증: 이중 미지 12조합 (`results/06_final_*/`)

| 구성 | AUC | F1평균/최악 | 이벤트 커버리지 | FA/h |
|---|---|---|---|---|
| **A: N5\|N4z 결합, 4노드 (채택)** | 0.930 | **0.698 / 0.636** | 0.986 | 9.7 |
| B: N4z 단독, rx1·4 | 0.943 | 0.644 / 0.230 | 0.987 | 8.7 |

  않는 것**(최악 F1 0.64 vs 0.23)이 배포 신뢰성의 본질이라 판단. B/C는 고AUC 대안으로 병기.

## 6. 오경보(FA/h)에 대한 정직한 해석

FA/h 9.7은 "**한 시간 내내 걷거나 팔을 휘젓는**" 스트림에서의 외삽치다 (음성 평가 스트림이
walk/handsup 120초 세션과 empty로만 구성). 또한 조합당 음성 스트림이 짧아(활동 4분 + 부재 22분)
**FA/h 값이 에피소드 1건당 약 2/h 단위로 양자화**된다 — 트레이드오프 곡선의 계단 형태가 그
때문이며, 절대값보다 "허용 FA ~7/h에서 커버리지 98%, ~3/h에서 40~70%"라는 형상을 읽어야 한다.
실제 생활에서 활동 시간 비율을 20~30%로 보면 체감 오경보는 시간당 2~3건 수준으로 추정된다.

**FA 소스 분해** (empty_q 임계값, 소스별 순수 스트림 외삽): walk 88.8/h ≫ handsup 29.6/h ≫
**empty 0.67/h** — 부재 상태 오경보는 임계값 규칙이 사실상 완전 억제하며, 오경보의 주범은
보행이다 (노드 근처 통과 시 주기적 스파이크, `results/07_demo/` 데모 타임라인 참조).

**"낙상 후 정지 확인" 필터 실험** (`results/07_demo/stillness_filter.md`): 경보 후 8초 내
[모션에너지 < factor × 부재 q95]가 1.2초 지속하지 않으면 기각 —
- factor 2.0: **커버리지 손실 0 (98.6% 유지)으로 walk FA −33%, handsup FA −8%** → 채택 권장
- factor 1.5: walk −64%, handsup −50%까지 억제되나 커버리지 90.6%로 하락 — 운영 선택지
- handsup도 팔 동작 사이 짧은 정지가 있어 이 필터만으로 완전 억제는 안 됨 — 근본 해결
  (자세 변화 감지 특징 등)은 후속 과제.

## 7. 새 집 배포 가이드 (`src/realtime_inference.py`)

```bash
# 1) 설치: TX 6시 기준 반시계로 rx1~4 (rx1·rx4가 TX 양옆) — 3집과 동일 규약
# 2) 부재 캘리브레이션 (10분 권장, 최소 1~2분)
python src/realtime_inference.py --calibrate new_home_empty_synced.csv
#    → models/new_home_calib.joblib (정규화 통계 + 자동 임계값)
# 3) 실시간 추론 (시뮬레이션 데모: synced.csv 스트림 재생)
python src/realtime_inference.py --simulate live_synced.csv
```
- 추론은 CPU에서 윈도우당 수 ms — ESP32 게이트웨이에 연결된 어떤 PC에서도 실시간 여유.
- 결측 프레임은 도착 즉시 선형 보간으로 채워 윈도우를 완성 (학습과 동일 처리).
- 데모 검증: home_C을 학습에서 제외한 번들로 home_C을 "새 집"처럼 캘리브→시뮬레이션
  (아래 8절 데모 결과).

## 8. 배포 시뮬레이션 데모 (정직한 조건: home_C 제외 학습)

조건: **home_C을 학습에서 완전히 제외**한 번들(`demo_bundle_no_P2.joblib`)로,
home_C empty **앞 10분만으로 캘리브레이션** 후 P3의 4개 세션 스트림을 재생.
(집은 미지, 인물은 다른 집에서 학습에 포함 — 인물까지 미지인 정량 평가는 5절 P6 결과가 담당)

자동 임계값: 부재 594윈도우, 점수 median 0.027 / q99.9 0.055 → **thr = 0.082**.

읽는 법 (`results/07_demo/demo_score_timeline.png`):
- 낙상 세션은 **지속적 고확률**, walk는 **임계값 언저리의 짧은 스파이크** — 점수 마진이 뚜렷해
  임계값·에피소드 로직으로 분리 가능한 구조.
- 반면 home_C의 handsup은 모델이 낙상과 혼동 — "제자리에 서서 상체만 크게 움직이는" 동작이
  이 집 기하에서 낙상의 신호 패턴과 겹친다. P6 집계에서 P2 FA/h가 높았던 주원인으로 추정.
  6절의 계층 필터(연속성·사후 정지 확인)가 필요한 지점이며, 낙상 후 "정지" 검증이 특히 유효할
  것 — handsup은 계속 움직이지만 낙상은 넘어진 뒤 정지하기 때문.

## 9. 한계와 다음 단계

1. **낙상 프록시의 한계**: 침대 위 안전 낙상은 실제 바닥 낙상과 충격 신호가 다를 수 있음.
   실제 배포 전 바닥 매트 낙상 데이터로 검증 필요.
2. **원룸 한정**: 3집 모두 ~19 m² 원룸. 방이 나뉜 집(NLOS 심화)에서는 재검증 필요.
3. **부재 vs 정지 상태**: "사람이 가만히 앉아/누워 있는 일상" 데이터가 없음 — 현재 비낙상은
   활동적 일상 + 완전 부재뿐. TV 시청 같은 정적 재실 상태에서의 오경보/미탐 특성은 미지.
4. **드리프트 장기전**: 부재 캘리브 유효성은 32분 스케일에서만 검증. 수일~수주 후 재캘리브
   전략(예: 야간 자동 부재 감지 시 통계 갱신) 필요.
5. **FA/h 절대값**: 6절의 계층 필터 미구현 상태의 수치.
6. 위상 특징, 도메인 적대 학습(DANN), 3집 이상 데이터 확보 시의 딥러닝 재도전은 미탐색/후속 과제.
